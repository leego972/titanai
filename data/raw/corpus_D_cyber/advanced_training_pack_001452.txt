--- DEFINING ZERO-DAY ---

A zero-day vulnerability is a software flaw unknown to the vendor.
"Day zero" = the day the vendor learns of it.
Before that: No patch exists. Defenders have no official mitigation. Attackers have an asymmetric advantage.

ZERO-DAY LIFECYCLE STAGES:

Discovery → Weaponization → Sale/Use → Detection → Patch → Deployment → EOL

  Discovery: Researcher, criminal, nation-state, or automated tool finds the bug
  Weaponization: Write reliable exploit targeting the vulnerability
  Sale/Use: Sell to broker, use in operation, report to vendor (bug bounty)
  Detection: Security researchers or defenders observe exploitation in the wild
  Patch: Vendor develops and releases fix
  Deployment: Users/organizations apply patch (often weeks to months)
  EOL: Vulnerability obsolete when affected software is retired

--- VULNERABILITY RESEARCH METHODOLOGIES ---

FUZZING:
  Coverage-guided fuzzing (AFL++, libFuzzer, WinAFL):
  Instrument binary with coverage tracking (LLVM passes, Intel PT hardware tracing).
  Mutate inputs based on coverage feedback: Mutations that reach new code = saved as seeds.
  
  Intelligence:
  Corpus management: Minimize corpus regularly (remove redundant seeds).
  Distillation: Keep only inputs that uniquely exercise code paths.
  Mutation strategies: Bit flip, byte flip, arithmetic (add/sub), known-value splicing,
  dictionary insertion (protocol keywords).
  
  Differential fuzzing:
  Same input to two implementations. Output difference = potential bug.
  Example: Same HTTP request parsed differently by Chrome vs Firefox → security-relevant divergence.
  Find: Parsing inconsistencies, behavior differences on edge cases.
  
  Grammar-based fuzzing:
  Input conforms to grammar (JSON, XML, JavaScript, HTTP).
  Generates semantically valid inputs that exercise deeper code paths.
  Tools: Domato (DOM fuzzer), Dharma (grammar-based), custom ANTLR grammars.
  
  Syzkaller (Linux kernel syscall fuzzer):
  Fuzzes system calls with coverage tracking (KCOV kernel instrumentation).
  Generates programs: Sequences of syscalls with correct types and dependencies.
  Outputs: C reproducers for each crash. Human-readable and compilable.
  Critical: Most Linux kernel CVEs in recent years found or confirmed with syzkaller.

STATIC ANALYSIS:
  Source code:
  CodeQL: GitHub's semantic analysis. Queries express vulnerability patterns.
  Semgrep: Fast, lightweight pattern matching.
  Coverity, Fortify: Enterprise-grade static analysis.
  
  Binary analysis:
  IDA Pro: The industry standard disassembler. IDAPython for automation.
  Ghidra: NSA-developed, free, excellent decompiler.
  Binary Ninja: Scriptable, modern, LLIL/MLIL intermediate representations.
  
  Taint analysis:
  Track data flow from untrusted source (network input, user file) to dangerous sink (memory operation, SQL query).
  If taint reaches sink without sanitization: Potential vulnerability.
  Tools: Triton (dynamic symbolic), CodeQL (static), Angr (static/dynamic).

DYNAMIC ANALYSIS:
  Symbolic execution:
  Angr: Python framework. Explore all execution paths symbolically.
  KLEE: LLVM-based, generates test cases for all paths.
  Triton: Dynamic symbolic execution. Run concrete, track constraints.
  
  Use case: Find inputs that reach a specific crash point.
  Angr finds: "Give input where condition X is true AND condition Y is false"
  → Generates exact byte sequence to trigger vulnerability.
  
  Emulation-based:
  QEMU: Full system emulation. Run firmware, IoT, exotic architectures.
  Unicorn Engine: CPU emulator library. Emulate code snippets in isolation.
  Useful for: Embedded device firmware analysis, shellcode analysis without OS.
  
  Dynamic instrumentation:
  Frida: JavaScript API for runtime instrumentation. Works on iOS, Android, Windows, Linux.
  Pin (Intel): Binary instrumentation framework. Write pintool for custom analysis.
  DynamoRIO: Dynamic binary instrumentation. Lower overhead than Pin.

PATCH DIFFING:
  Vendors release patches. Diff old vs new binary to find what changed.
  Find the changed function → understand what was wrong → write exploit for unpatched systems.
  
  Tools:
  BinDiff (Zynamics/Google): Graph-based binary comparison. Visual function diffs.
  Diaphora: Open-source BinDiff alternative. SQLite export for automation.
  
  Process:
  1. Download patched and unpatched binary
  2. Load both in IDA/Ghidra
  3. Run BinDiff → See all changed functions
  4. Focus on changed functions with security relevance (parser, crypto, input handling)
  5. Understand the old code vs new code → What was the vulnerability?
  6. Write exploit before patch reaches users (1-day/n-day exploitation)
  
  Timeline: Patch Tuesday (Microsoft second Tuesday) → Exploit developers have
  active analysis in hours. N-day exploits often functional within 72 hours.

--- EXPLOIT PRIMITIVES ---

MEMORY CORRUPTION CLASSES:

Buffer Overflow (stack):
  Writing past end of stack buffer → overwrite return address, saved RBP, canary.
  Classic but rare in modern code (bounds-checked languages, Stack Canaries, ASLR).
  Still common in: C/C++ legacy code, IoT firmware, protocol parsers, OS kernels.

Use-After-Free (UAF):
  Pointer to freed memory used after free.
  Allocator may reuse memory → attacker controls what's there.
  
  Exploitation:
  1. Spray allocations of attacker-controlled object (same size as freed object)
  2. Trigger free of target object
  3. Allocator reuses memory → places attacker's object there
  4. Victim code accesses "freed" object → actually accesses attacker's data
  5. If object contains function pointers/vtable → control flow hijack
  
  Browser UAF pattern:
  DOM node freed → JS engine reuses memory → DOM event handler on freed node fires
  → Handler dereferences vtable from attacker-controlled memory → RCE.

Type Confusion:
  Object accessed as wrong type. Field offsets interpreted differently.
  Common in JavaScript JIT compilers: Shape/class assumptions violated.
  
  V8 example:
  // Optimizer assumes array[idx] is always number
  // If attacker changes array type mid-execution: JIT reads field at wrong offset
  // With controlled type change: Read/write arbitrary memory via "corrupted" type
  
  SpiderMonkey Ion type confusion:
  // JSObject has type pointer + data
  // Confuse JSObject with ArrayBuffer
  // length field of "fake ArrayBuffer" = arbitrary value
  // Read/write out-of-bounds by indexing beyond fake length

Integer Overflow:
  Arithmetic wraps around max value. Size calculation wrong → undersized buffer.
  
  Classic pattern:
  uint32_t size = user_controlled_size + 8;
  // If user_controlled_size = 0xFFFFFFF8:
  // 0xFFFFFFF8 + 8 = 0x100000000 → wraps to 0 (32-bit) or 8 (if truncated from 64-bit)
  // malloc(0) or malloc(8) → tiny buffer
  // Then copy user_controlled_size bytes → massive overflow
  
  Fix: Always validate before arithmetic. Use safe-integer libraries.

Race Condition (TOCTOU):
  Check resource state, then use resource. Between check and use: State changes.
  
  Kernel TOCTOU:
  1. Kernel checks: "Is this file symlink?" → No, proceed.
  2. Attacker thread: Replace regular file with symlink.
  3. Kernel uses: Follows symlink → accesses wrong file.
  4. Attacker: Points symlink to /etc/shadow → kernel writes there.
  
  Example: Dirty Cow (CVE-2016-5195):
  Race in copy-on-write handling. Win race → write to read-only memory mapping.
  Exploit: Write to /etc/shadow (mapped read-only) → change root password.

--- BROWSER EXPLOITATION IN DEPTH ---

JAVASCRIPT ENGINE ARCHITECTURE (V8):

Ignition (interpreter): Generates bytecode. Runs code immediately.
SparkPlug (fast compiler): No optimization. Fast compilation. Above Ignition.
Maglev (mid-tier compiler): Medium optimization. Introduced 2023.
TurboFan (optimizing compiler): Full optimization after profiling.

Exploitation path in V8:
1. OOB (Out-of-Bounds) read: Defeat ASLR by reading heap pointer from adjacent object.
2. OOB write: Corrupt adjacent object's field (e.g., array's length or buffer pointer).
3. Fake ArrayBuffer: Create ArrayBuffer whose backing store pointer points to arbitrary memory.
4. Read/write primitive: Use fake ArrayBuffer to read/write anywhere in process memory.
5. Code execution: Write shellcode / ROP chain to executable region, or find JIT code.

WebAssembly exploitation:
  WASM JIT compiles to native code → WASM memory is mapped as RWX (execute).
  If you can write to WASM memory region: Write shellcode.
  V8 hardened this: Now uses RW then RX transition.
  
  WASM type confusion → corrupt WASM memory object → write to wrong region → RCE.

--- KERNEL EXPLOITATION ---

LINUX KERNEL PATHS:

eBPF exploitation (CVE-2021-3490, CVE-2022-23222):
  eBPF: Extended Berkeley Packet Filter. Run sandboxed programs in kernel.
  JIT compiler for eBPF bytecode. Verifier supposed to prevent dangerous code.
  
  Attack: Verifier bypass → JIT compiles arbitrary code → kernel code execution.
  Verifier bugs: Off-by-one in tracking value ranges → verifier approves dangerous code.
  
  Result: Unprivileged user → kernel code execution (full root).
  eBPF requires CAP_BPF (or CAP_SYS_ADMIN on older kernels).
  But: Container escapes where attacker has kernel access within container.

io_uring exploitation:
  Linux 5.1+ async I/O mechanism. Extensive kernel attack surface.
  2022-2023: Multiple CVEs. PoC exploit chains demonstrated.
  Cloudflare/Google disabled io_uring in production due to repeated vulnerabilities.
  
  Attack surface: SQE (submission queue entry) operations → kernel operations with user-controlled data.

Dirty Pipe (CVE-2022-0847):
  Linux 5.8+. Write to arbitrary files opened read-only.
  Root cause: Pipe page cache flag not cleared on new pipe.
  Exploit: Write malicious data to pipe → splice read-only file into pipe → overwrites file.
  Impact: Overwrite SUID binaries → privilege escalation to root.
  
  One-line PoC (simplified):
  1. Open /etc/passwd read-only
  2. Create pipe
  3. Fill pipe buffer (to set flags)
  4. Drain pipe
  5. Splice /etc/passwd into pipe (page cache entry, flags not cleared)
  6. Write attacker data into pipe → writes into /etc/passwd page cache → overwrites file

PwnKit (CVE-2021-4034):
  pkexec: SUID binary. Part of PolicyKit.
  Memory corruption in argument parsing. Present since 2009.
  Universal local privilege escalation: Works on all Linux distros.
  
  Exploit technique:
  Manipulate argc=0 (no arguments). Out-of-bounds read from argv → writes environment variable.
  Overwrite PATH → pkexec loads shared library → library executes as root.

WINDOWS KERNEL PATHS:

Token privilege abuse:
  Every process has an access token. Token contains: Privileges, groups, SID.
  SeDebugPrivilege: Debug any process (including SYSTEM processes).
  SeImpersonatePrivilege: Impersonate tokens from privileged services.
  SeAssignPrimaryTokenPrivilege: Assign primary token to process.
  
  Token impersonation: If process has SeImpersonatePrivilege (IIS, service accounts):
  Create named pipe → trick privileged service into connecting → impersonate their token.
  Tools: Juicy Potato, Rotten Potato, PrintSpoofer.

ALPC (Advanced Local Procedure Call):
  Windows IPC mechanism. Complex, many attack surfaces.
  Historical CVEs: Type confusion, buffer overflows in kernel ALPC handling.
  Modern: Heavily audited but still explored.

iOS/macOS KERNEL PATHS:

Mach ports:
  iOS/macOS IPC: Mach messages between processes.
  Mach port holds on deallocated objects → UAF via Mach message.
  Mach port race conditions.
  
  Mitigation: "Hardened runtime" on macOS, sandbox restrictions.

PAC (Pointer Authentication Codes):
  ARM v8.3+. Cryptographic signing of pointers.
  Return addresses and function pointers signed with secret key.
  Forge pointer without correct key → PAC fault.
  
  Bypass techniques:
  - Find oracle: Code that signs/verifies a pointer you control → forge signature.
  - Find unprotected code path: Not all pointers covered by PAC.
  - Physical attack: Extract key from chip (impractical for remote exploits).

--- INFECTION VECTORS IN TECHNICAL DETAIL ---

1. FORCEDENTRY (CVE-2021-30860) — Zero-Click iMessage:
  Target: iOS 14.4 – 14.6 (2021)
  Delivery: iMessage attachment
  File disguise: Files named with .gif extension but actually PDF content
  
  Technical chain:
  a) BlastDoor: Apple's sandbox for processing iMessage attachments.
     BlastDoor runs in isolated process, memory-safe (Swift), no JIT.
     FORCEDENTRY bypassed BlastDoor via PassKit (Wallet) path.
  
  b) JBIG2 decoder vulnerability:
     JBIG2: Fax compression format. Rarely used. Parser complex and old.
     CVE: Integer overflow in JBIG2 decompressor in Core Graphics (ImageIO).
     
  c) Exploitation of JBIG2:
     JBIG2 has a "segment" type that allows copying memory regions.
     Crafted JBIG2: Uses segment operations to build a Turing-complete environment.
     NSO engineers built a "JBIG2 computer": Memory operations implement
     boolean logic circuits within JBIG2 segment operations.
     This virtual CPU runs a stage-1 exploit that bootstraps from within
     the limited JBIG2 processing environment.
  
  d) Result: Kernel memory corruption → code execution → sandbox escape → Pegasus installed.
  e) Zero-click: No tap, no look required. Just receives the message.

2. BLASTPASS (CVE-2023-41064 + CVE-2023-41061) — Zero-Click PassKit:
  Target: iOS 16.6 (2023)
  Delivery: iMessage with PassKit attachment (.pkpass wallet file)
  
  Technical:
  PassKit = wallet passes (boarding passes, loyalty cards).
  iOS processes PassKit attachments through iMessage.
  CVE-2023-41064: Buffer overflow in ImageIO processing of embedded images in PassKit.
  CVE-2023-41061: Validation issue in PassKit.
  
  Two vulnerabilities chained:
  First CVE: Initial code execution within processing context.
  Second CVE: Escalate to full exploit chain.
  Zero-click: PassKit processed automatically on receipt.

3. KISMET (2020) — Zero-Click iMessage:
  Target: iOS 13.x
  Delivery: iMessage
  Vulnerability: Memory corruption in image parser within iMessage.
  No user interaction. Receipt of message triggers exploit.

4. TRIDENT (2016) — Three Zero-Days:
  Discovered because NSO made a mistake: Sent exploit to Ahmed Mansoor (wrong target).
  Mansoor sent link to Citizen Lab instead of clicking.
  
  Chain:
  CVE-2016-4657: WebKit memory corruption (clicking malicious link)
  CVE-2016-4655: Kernel information leak (defeat KASLR)
  CVE-2016-4656: Kernel memory corruption → privilege escalation
  
  First-ever documented Pegasus infection chain. Required clicking a link.
  NSO subsequently developed zero-click vectors.

--- PAYLOAD TECHNICAL ARCHITECTURE ---

MODULAR DESIGN:
  Loader: Initial executable, drops modules.
  Core: Persistence, C2 communications, module management.
  Plugins: Capability modules loaded/unloaded remotely.
  
  Each capability = separate encrypted plugin.
  Operators enable only needed capabilities per target.
  Minimizes footprint if partially detected.

PERSISTENCE (iOS):
  Since iOS doesn't permit persistent daemons normally:
  Pegasus: Exploits kernel to disable code-signing enforcement.
  Installs as: Daemon process similar to legitimate system services.
  Names chosen: Similar to real Apple daemon names (e.g., resembling "mediaserverd").
  Launch daemon plist: Added to LaunchDaemons directory.
  Kernel hooks: Hooks process listing to hide itself from ps/top output.
  Persistence trigger: LaunchDaemon ensures restart after device reboot.
  
  Note: Memory-only variants don't survive reboot (BLASTPASS in some configurations).
  Requires re-infection on next reboot. Operators may re-infect regularly.

C2 COMMUNICATIONS:
  Protocol: HTTPS on port 443 (looks like normal web traffic).
  Domain fronting: Use CDN (Cloudflare, Akamai, Fastly) as front.
    - Initial connection to CDN (legitimate domain in TLS SNI)
    - CDN proxies to actual C2 server
    - Network observer sees: Connection to Cloudflare/Akamai (normal)
    - Actual destination: Obscured
  
  Certificate: Valid TLS certificate (often from CDN provider).
  Custom encryption: Additional layer beyond TLS. Even SSL inspection misses payload content.
  
  Beaconing: Regular callbacks to C2. Interval configurable by operator.
  Exfiltration: Only when on WiFi (avoid cellular data detection and metered charges).
  Timing: Exfiltration often at night when device is charging and on WiFi.
  Throttling: Limit data volume to stay under unusual usage thresholds.

DATA COLLECTION MODULES:

Messages module:
  Signal: Reads from Signal's encrypted database directly (bypasses encryption).
  WhatsApp: Reads messages from app's database files.
  iMessage: Direct access to messages database.
  Telegram, Line, Gmail: Similar approach — read app databases directly.
  Note: End-to-end encryption irrelevant when spyware reads plaintext on-device.

Audio/Video module:
  Microphone activation: Hooks system audio APIs. Records without indicator.
  Camera activation: Takes photos/video silently.
  Screen capture: Periodic screenshots or video recording.
  Environment audio: Activates mic to capture room audio when device is "idle".

Location module:
  GPS: Direct GPS coordinates.
  WiFi positioning: Known WiFi networks → location inference.
  Cell tower triangulation: Cell tower IDs → approximate location.
  Continuous tracking: Updates location on configurable interval.

Keylogger module:
  Hooks UIKit text input APIs.
  Captures: Passwords, messages, URLs, any text typed on device.
  Stores locally, encrypted. Exfiltrated to C2.

Credential theft module:
  iOS Keychain: Extracts stored passwords, certificates, keys.
  Third-party password managers: Reads from app databases.
  Browser passwords: Safari's stored credentials.

ANTI-FORENSICS:
  Self-destruct: If signs of investigation detected → delete all traces.
  Debugging detection: If LLDB/GDB attached → abort or behave normally.
  Virtual machine detection: If in analysis environment → behave differently.
  Jailbreak detection: Paradoxically, Pegasus hides if jailbreak detected

--- EDR DEEP DIVE ---

HOW MODERN EDR COLLECTS TELEMETRY:

Windows kernel callbacks:
  PsSetCreateProcessNotifyRoutine: Notified on every process creation/termination.
  PsSetCreateThreadNotifyRoutine: Notified on every thread creation.
  PsSetLoadImageNotifyRoutine: Notified on every DLL/driver load.
  CmRegisterCallback: Notified on every registry operation.
  
  EDR installs callbacks in kernel → sees every process, thread, DLL, registry operation.
  This is why EDR is so effective: Kernel-level visibility into everything.

ETW (Event Tracing for Windows):
  Windows instrumentation framework. Providers log events.
  EDR subscribes to security-relevant providers:
  Microsoft-Windows-Threat-Intelligence: Process injection, shellcode detection.
  Microsoft-Windows-Security-Auditing: Authentication, logon, privilege use.
  Microsoft-Kernel-Process: Process and thread operations.

User-mode hooks (common but less reliable):
  Patch ntdll.dll exported functions with detour to EDR code.
  Every API call intercepted for analysis.
  Weakness: Direct syscalls bypass user-mode hooks entirely.
  Modern EDR defense: ETW Threat Intelligence (kernel-level, can't be bypassed without kernel exploit).

LEADING EDR TECHNICAL COMPARISON:

CrowdStrike Falcon:
  Architecture: Lightweight sensor + Falcon Insight (cloud processing).
  Differentiator: Threat Graph — correlates telemetry across 3M+ endpoints globally.
  When your sensor sees unknown malware: Threat Graph knows if 5000 other endpoints saw it.
  IOAs (Indicators of Attack): Behavioral patterns, not file hashes. Detects novel malware.
  Exploit prevention: User mode memory hooking + kernel callbacks.
  
  Falcon Overwatch: Managed threat hunting team. 24/7 human analysts watching the Threat Graph.
  
SentinelOne Singularity:
  Architecture: Autonomous response. No cloud lookup required.
  Storyline: Correlates process events into a full attack narrative automatically.
  "One click rollback": Reverse all changes made by malware (file, registry, process).
  Deep Visibility: Raw telemetry available for hunting via query language.
  
Microsoft Defender for Endpoint:
  Architecture: Tightly integrated with Windows kernel. Native.
  ASR (Attack Surface Reduction) rules: Specific behavioral blocks.
    - Block process creation from Office apps: Stops macro-based malware spawning cmd.exe
    - Block LSASS credential dumping
    - Block Win32 API calls from Office macros
  Integration: Conditional Access, Azure AD, Intune. Identity + endpoint correlation.

--- NDR (NETWORK DETECTION AND RESPONSE) ---

DARKTRACE: ENTERPRISE IMMUNE SYSTEM:
  Philosophy: Don't define what's bad. Learn what's normal. Detect deviations.
  
  SelfLearning AI:
  - Models every device, user, network behavior over 1-3 weeks.
  - Creates "pattern of life" for each entity.
  - Detects: Anything statistically unusual for that entity.
  
  Example:
  Server X normally: Receives web traffic, connects to 3 internal DBs, no external connections.
  Anomaly: Server X suddenly makes DNS requests for high-entropy domains.
  Darktrace: Alerts (0 historical precedent for this behavior from this server).
  This detects DGA-based C2 even if the domain is brand new and not in any threat feed.
  
  Antigena:
  Autonomous response. Can: Block specific connections, slow down exfiltration, isolate devices.
  Speed: Responds in 0.2ms (faster than human can react).

--- XDR TECHNICAL ARCHITECTURE ---

XDR vs SIEM vs EDR:

  EDR: Endpoint-only. Deep visibility on endpoint. No network context.
  SIEM: Aggregates logs from everywhere. Correlation rules. But: Log-based, not agent-based.
        Limited endpoint context. Rules-based detection misses novel attacks.
  XDR: EDR + Network + Cloud + Email + Identity. Unified correlation. 
       Uses agent telemetry (not just logs) for higher-fidelity detection.
       AI/ML correlation across all data sources simultaneously.

XDR KILL CHAIN CORRELATION:
  Attacker email hits mailbox → Email security detects suspicious link.
  User clicks link → Web proxy logs access to suspicious domain.
  Browser downloads file → EDR sees file written + process executed.
  Process spawns PowerShell → EDR sees encoded command.
  PowerShell beacons to C2 → NDR detects C2 pattern.
  
  Without XDR: Each tool sees one piece. Analysts must manually connect.
  With XDR: Single automated story. "Starting with this email, here is the full attack chain."
  Mean time to detect: 197 days (without) → hours (with XDR + 24/7 SOC).

--- DECEPTION TECHNOLOGY ---

CANARY TOKENS IN DEPTH:

DNS canary token:
  Place unique subdomain in configuration files, code, documents.
  Any DNS lookup of that subdomain → attacker is reading your files.
  token = "internal-db-creds-v2.canary.yourdomain.com"
  Attacker reads config file, tries to resolve → you're alerted instantly.
  
  Production deployment:
  aws_access_key_id = "AKIAIOSFODNN7EXAMPLE"  # looks real, is canary
  aws_secret_access_key = "wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY"
  
  # Canary token (Thinkst Canary) AWS credential:
  # When someone tries to use these credentials → alerts security team immediately.
  # Zero false positives: Nobody should ever USE these credentials.
  
Active Directory canary:
  Create fake "service account" with tempting name: "svc_backup_admin".
  No legitimate process ever authenticates with this account.
  Any authentication attempt = attacker trying discovered credentials.
  Zero false positive: Real service accounts have documented usage.

HONEYNET ARCHITECTURE:
  Deploy realistic fake environment:
  - Fake domain: honeycorp.local with legitimate-looking names
  - Fake servers: Exchange (honeypot), file server, domain controller
  - Fake credentials: Seeded on "real" systems
  - Fake data: Sensitive-looking files that are actually monitored
  
  When attacker enters:
  Finds credentials on legitimate server → Tries them on honeypot domain controller.
  Honeypot DC: Accepts everything, logs everything, alerts immediately.
  Security team: Attacker just revealed their tools, TTPs, lateral movement path.
  Can let attacker continue (watch and learn) or terminate (cut off access).

iOS FORENSIC ARTIFACTS (from Citizen Lab / Amnesty research):

Crash logs (diagnostics/crashes/):
  Exploit attempts sometimes crash processes before succeeding.
  Crash in unexpected process (e.g., imagent, imtransferagent) at time of suspected infection.
  Backtrace in crash log: May show exploit chain.

Datausage anomaly:
  Pegasus exfiltrates primarily over WiFi.
  High data transfer late at night from unexpected processes.

Process history:
  From sysdiagnose files (full system diagnostic dump):
  adb pull iOS diagnostic → contains ps output, network connections, process lists at time of dump.

--- IR PLAYBOOK: SUSPECTED ADVANCED SPYWARE ---

T=0: Suspected compromise notification
  Source: Citizen Lab notification, MVT finding, behavioral observation (battery drain, heat, unusual traffic).

T+0 to T+30 minutes:
  DO NOT reboot device: Rebooting destroys in-memory evidence.
                        Many Pegasus variants are memory-only (no persistence).
  DO NOT wipe device:  Evidence destroyed before forensics.
  DO NOT update: May trigger anti-forensic self-destruct.
  
  Isolate network: Enable Airplane Mode.
  Photograph screen: Capture current state visually.
  Time-stamp: Note exact time you received notification or suspected compromise.

T+30 minutes to T+2 hours:
  Forensic acquisition:
  iOS: Trigger sysdiagnose. Create encrypted backup (iTunes). Create logical image.
  Android: ADB backup. Enable USB debugging first if not already.
  
  Evidence chain:
  Hash all acquired files immediately: SHA-256.
  Document: Date, time, device model, iOS version, who acquired.

T+2 to T+24 hours:
  MVT analysis on acquired evidence.
  Check against latest IOC list.
  Manual review of suspicious findings.
  
T+24 to T+72 hours:
  Scope assessment: Who else in the organization may be targeted?
  Threat actor identification: Which nation-state? Based on target profile and infrastructure.
  Remediation: Replacement device, fresh setup (NOT from backup), new accounts.
  Communications: Inform affected individual. Change all passwords from clean device.

--- INTERNATIONAL LEGAL LANDSCAPE ---

Computer Fraud and Abuse Act (CFAA, US):
  Criminalizes unauthorized access to computer systems.
  Security researchers: "Authorized" access ambiguous. Chilling effect on research.
  Van Buren v. United States (2021 Supreme Court): Limits overly broad CFAA interpretation.
  Still: Careful scoping of research required.

EU Network and Information Systems (NIS2, 2023):
  Expanded scope: 18 sectors now must meet cybersecurity requirements.
  Reporting: 24-hour initial notification, 72-hour full report to CSIRT.
  Penalties: Up to €10M or 2% global turnover for essential entities.

Wassenaar Arrangement:
  International export control regime.
  "Intrusion software" now subject to export controls.
  Pegasus/commercial spyware: May require government approval for export.
  NSO's relationship: Israeli export license required per Israeli law.
  Criticism: Export controls issued, then revoked, inconsistently enforced.

EU Surveillance Regulation (proposed 2023):
  Response to Pegasus scandal in EU member states (Hungary, Greece, Spain).
  Proposed: Framework governing member states' use of spyware.
  EU Parliament Pegasus Committee: Recommended suspension of states that abused.

US Executive Order 14086 (2022):
  Restricts intelligence community from purchasing commercial spyware.
  Response: Landmark US domestic action against commercial surveillance.

CITIZEN LAB AND ACCOUNTABILITY:
  Citizen Lab (University of Toronto): Primary independent researcher tracking Pegasus.
  Methods: Fingerprint Pegasus infrastructure, scan internet for infrastructure.
  Notify targets: Inform individuals whose devices show IOC matches.
  Work with Amnesty, Access Now, human rights organizations.
  
  Pegasus Project (2021): Consortium of 17 news organizations.
  Leaked list: 50,000 phone numbers selected as potential Pegasus targets.
  Confirmed infections: Multiple heads of state, journalists, activists.
  Impact: NSO placed on US Entity List. Multiple lawsuits (Apple, WhatsApp vs. NSO).
