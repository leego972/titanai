Question: <p>From some forum I came to know that Multiple database support is added in Django at lower level, but the higher level apis are not added yet.</p>

<p>Can anyone please tell me how one can achieve multiple database connections in Django.</p>

<p>Does anyone have any idea by when Django will fully/officially support Multiple database connections.</p>

Answer: <p>If you read a few of the many (<em>many</em>) threads on this subject in django-dev, you will see that what <em>looks</em> straightforward, isn't. If you pick a single use case, then it looks easy, but as soon as you start to generalize in any way you start to run into trouble.</p>

<p>To use the above-referenced thread as an example, when you say "multiple databases", which of the following are you talking about?</p>

<ul>
<li>All DB on the same machine under the same engine.</li>
<li>All DB on same machine, different engines (E.g. MySQL + PostgreSQL)</li>
<li>One Master DB with N read-only slaves on different machines.</li>
<li>Sharding of tables across multiple DB servers.</li>
</ul>

<p>Will you need:</p>

<ul>
<li>Foreign keys across DBs</li>
<li>JOINs across machines and/or engines</li>
<li>etc. etc.</li>
</ul>

<p>One of the problems with a slick ORM like Django's is that it hides all of those messy details under a nice paint job. To continue to do that, but to then add in any of the above, is Not Easy (tm).</p>
