Question: <p>We know that Python provides a  lot of productivity over any compiled languages. We have programming in C# &amp; need to write the unit test cases in C# itself. If we see the amount of code we write for unit test is approximately ten times more than the original code. </p>

<p>Is it ideal choice to write unit test cases in IronPython instead of C#? Any body has done like that? I wrote few test cases, they seems to be good. But hairy pointy managers won't accept.</p>

Answer: <p>Python is excellent for UnitTesting C# code.  Our app is 75% in Python and 25% C#(Python.Net), and our unit tests are 100% python.  </p>

<p>I find that it's much easier to make use of stubs and mocks in Python which is probably one of the most critical components that enable one to write effective unittests.</p>
