Question: <p>I tend to use <a href="http://en.wikipedia.org/wiki/SQLite">SQLite</a> when doing <a href="http://en.wikipedia.org/wiki/Django%5F%28web%5Fframework%29">Django</a>
development, but on a live server something more robust is
often needed (<a href="http://en.wikipedia.org/wiki/MySQL">MySQL</a>/<a href="http://en.wikipedia.org/wiki/PostgreSQL">PostgreSQL</a>, for example).
Invariably, there are other changes to make to the Django
settings as well: different logging locations / intensities,
media paths, etc.</p>

<p>How do you manage all these changes to make deployment a
simple, automated process?</p>

Answer: <p>I have two files. <code>settings_base.py</code> which contains common/default settings, and which is checked into source control. Each deployment has a separate <code>settings.py</code>, which executes <code>from settings_base import *</code> at the beginning and then overrides as needed.</p>
